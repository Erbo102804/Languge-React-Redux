## 1. Введение

EduHub — это веб-приложение онлайн-школы программирования. Это
одностраничное приложение (SPA), реализованное на React 19 с
использованием Redux Toolkit в качестве менеджера состояния и
React Router для навигации.

Приложение предназначено для двух категорий пользователей:

- **Студенты** — просматривают каталог курсов, читают подробное
  описание, записываются на курсы, видят своё расписание и личный
  кабинет, общаются с преподавателем через встроенный чат.
- **Администраторы** (любой авторизованный пользователь) — управляют
  каталогом курсов: создают новые, редактируют существующие, удаляют
  устаревшие. Каждая операция отправляется на удалённый REST API.

Основные принципы реализации:

- разделение ответственности (UI, бизнес-логика, работа с данными);
- декларативный подход к состоянию через Redux Toolkit;
- единый паттерн загрузки данных через `createAsyncThunk`;
- обязательная обработка трёх состояний: loading, error, empty;
- сохранение пользовательских данных между сессиями через
  `localStorage`.

## 3. Архитектура проекта

Архитектура слоистая, в каждом слое — чёткая зона ответственности:

**Слой представления (UI)**
Папки `src/pages/` и `src/components/`. Содержат React-компоненты:
страницы и переиспользуемые блоки. Компоненты получают данные через
`useSelector` и отправляют действия через `useDispatch`.

**Слой маршрутизации**
Папка `src/routes/`. Содержит конфигурацию роутов через
`react-router-dom`. Корневой компонент роутинга — `AppRoutes.jsx`.

**Слой состояния (Redux)**
Папка `src/redux/`. Содержит `store.js` и `slices/` — слайсы для
каждой доменной сущности: курсы, авторизация, записи на курсы и т.п.
Каждый слайс инкапсулирует своё состояние и редьюсеры.

**Слой сервисов**
Папка `src/services/`. Содержит код, отвечающий за работу с
внешними источниками данных (REST API, локальные JSON-файлы).
Сервисы возвращают чистые промисы и не знают о Redux. Это делает
их легко заменяемыми и тестируемыми.

**Слой утилит**
Папка `src/utils/`. Содержит чистые функции-помощники: форматирование
цены, формирование расписания, работа со строками.

**Слой хуков**
Папка `src/hooks/`. Содержит кастомные React-хуки: `useAuth`,
`useMyEnrollments`, `useNotify`. Они инкапсулируют типичные обращения
к store и упрощают подписку на состояние.

Поток данных:

    Пользователь → Компонент → dispatch(thunk)
        ↓
    Service (fetch) → API/localStorage
        ↓
    Reducer обновляет state
        ↓
    Компонент перерисовывается через useSelector

## 5. Redux: store и slices

Корневое хранилище собрано в `src/redux/store.js` через
`configureStore` и состоит из девяти слайсов:

### authSlice
Авторизация пользователя. Состояние: `{ user, isAuthenticated, error }`.
Редьюсеры: `login`, `register`, `logout`, `clearError`. Список
зарегистрированных пользователей хранится в `localStorage` под ключом
`users`, текущий пользователь — под ключом `user`.

### coursesSlice
Курсы. Состояние:
`{ courses, currentCourse, loading, mutating, error }`. Содержит
пять async-thunks:

- `fetchCourses` — GET, список курсов из локального JSON;
- `fetchCourseById` — GET, отдельный курс;
- `createCourse` — POST на JSONPlaceholder;
- `updateCourse` — PUT на JSONPlaceholder;
- `deleteCourse` — DELETE на JSONPlaceholder.

Флаг `loading` показывает загрузку списка, `mutating` — выполнение
CRUD-операции. Это позволяет блокировать кнопки сохранения и
показывать индикаторы только в нужных местах.

### enrollmentsSlice
Записи студентов на курсы. Состояние: `{ items: [] }`, где каждая
запись содержит `userId`, `courseId`, `day`, `time`, `instructor`,
`courseTitle`, `image`, `level`, `duration`, `price`, `enrolledAt`.
Редьюсеры: `enroll`, `unenroll`, `clearUserEnrollments`. Селекторы:
`selectUserEnrollments(userId)`, `selectIsEnrolled(userId, courseId)`.
Все записи сохраняются в `localStorage` под ключом `enrollments`.

### notificationsSlice
Очередь тост-уведомлений. Состояние: `{ items: [] }`. Каждое
сообщение содержит `id`, `text`, `type` (`success`, `info`, `error`).
Редьюсеры: `pushNotification`, `removeNotification`. Компонент
`<Toast>` автоматически удаляет уведомление через 3.5 секунды.

### chatSlice
Сообщения чата с преподавателем. Состояние: `{ messages: [] }`. Каждое
сообщение содержит `id`, `userId`, `courseId`, `teacher`, `role`
(`user` или `teacher`), `text`, `ts`. Сохраняется в `localStorage`
под ключом `chat_messages`.

### newsSlice, teachersSlice
Содержат `fetchNews` и `fetchTeachers` соответственно. Данные грузятся
из локального JSON с задержкой 1.0-1.2 секунды для демонстрации
loading-состояния.

### studentsSlice
Простой слайс с фиксированным начальным списком студентов и
редьюсерами `addStudent` / `removeStudent`. Используется на странице
«Студенты».

### uiSlice
Состояние UI-фильтров. Содержит:
- `coursesSearch` — текст поиска по курсам;
- `coursesLevel` — выбранный уровень (`all`, `Начинающий`, `Средний`,
  `Продвинутый`).

Редьюсеры: `setCoursesSearch`, `setCoursesLevel`, `resetCoursesFilters`.
Селектор `selectFilteredCourses` возвращает отфильтрованный по обоим
параметрам список.

## 6. Работа с API

Приложение работает с двумя типами источников данных:

**Локальные JSON-файлы** в `public/data/`. Используются для каталога
курсов, ленты новостей и списка преподавателей. Запросы идут через
функцию `localJson(path, delayMs)` из `apiClient.js`. Искусственная
задержка (1.0-1.5 с) добавлена для демонстрации индикаторов загрузки.

**Внешний REST API: JSONPlaceholder**
(`https://jsonplaceholder.typicode.com`). Используется для
демонстрации настоящих HTTP-операций CRUD. Это публичный fake REST
API, доступный всем разработчикам. Запросы реализованы через
`apiClient.post`, `apiClient.put`, `apiClient.delete`. Каждый запрос
оборачивается в `AbortController` с таймаутом 5 секунд — если
сеть медленная или недоступна, UI не зависает.

CRUD-сценарий:
1. Пользователь жмёт «Добавить курс».
2. Срабатывает `dispatch(createCourse(data))`.
3. Thunk вызывает `createCourseRemote(data)`, который шлёт `POST` на
   `https://jsonplaceholder.typicode.com/posts`.
4. JSONPlaceholder возвращает `201 Created` с присвоенным `id`.
5. Reducer добавляет новый курс в `state.courses.courses`.
6. UI перерисовывается, появляется toast «Курс добавлен».

Аналогично для PUT и DELETE.

## 8. Описание страниц

### HomePage (главная)

Содержит hero-блок с описанием платформы и статистикой (число
студентов, курсов, преподавателей), список топ-3 курсов, ленту

### CoursesPage (каталог)

Отображает заголовок страницы и компонент `<CoursesList />` без

названию/описанию/преподавателю и кнопки уровня. Для авторизованных —
кнопка «+ Добавить курс».

### CourseDetailPage (детальная страница курса)

Содержит:
- картинку и название курса, уровень, описание;
- блок мета-информации: преподаватель, длительность, число уроков,
  рейтинг, расписание;
- блок цены и количества студентов;
- кнопку «Записаться на курс» (или бейдж «Вы записаны» с кнопками
  «Личный кабинет» и «Отписаться» — после записи);
- секцию «О курсе» с полным описанием;
- секцию «Что вы изучите» со списком тем;
- виджет чата с преподавателем (плавающая кнопка справа внизу).

Для авторизованных пользователей — кнопки «Редактировать» и
«Удалить» в шапке.

### SchedulePage (расписание)

Две таблицы:
- «Моё расписание» — курсы текущего пользователя, отсортированные по
  дню недели и времени, со ссылками на детальные страницы;
- «Общее расписание» — справочная таблица всех занятий школы.

Для неавторизованных пользователей в верхней секции показывается
заглушка с кнопкой «Войти».

### ProfilePage (личный кабинет)

Карточка пользователя (аватар-инициал, имя, email, число курсов и
общая стоимость) и сетка карточек «Мои курсы» с указанием дня,
времени, преподавателя, длительности и кнопкой «Отписаться».

### LoginPage / RegisterPage

Формы входа и регистрации с валидацией. После успеха — редирект на
главную и автоматический вход.

### StudentsPage, AboutPage

Простые информационные страницы.

## 9. Описание компонентов

### Header

Шапка приложения. Содержит логотип, навигационное меню (React Router
`NavLink` с активным состоянием), бургер-меню для мобильных
устройств. В правой части — блок авторизации: имя пользователя
(ссылка на профиль) и кнопка «Выйти» для авторизованных, либо
кнопки «Войти» / «Регистрация» для гостей.

### Loader

Простой индикатор загрузки с анимированным спиннером и поясняющим
текстом.

### Toast

Глобальный контейнер тост-уведомлений в правом верхнем углу. Каждое
уведомление имеет иконку (по типу) и кнопку закрытия. Удаляется
автоматически через 3.5 секунды или вручную.

### CoursesList

Сетка карточек курсов. Поддерживает параметр `limit` (для главной
страницы — показать только N курсов). На полной странице каталога
показывает панель фильтров (поиск + уровень) и счётчик найденных.
Для авторизованных — кнопка «+ Добавить курс» и иконки
редактирования/удаления на каждой карточке. Empty state с кнопкой
сброса фильтров — если результатов нет.

### CourseForm

Модальное окно с формой создания/редактирования курса. Все поля
валидируются перед отправкой. Кнопка сохранения блокируется во время
выполнения async-операции; пока запрос идёт — показывается надпись
«Сохранение...».

### ChatWidget

Плавающий чат-виджет внизу страницы курса. Поведение:
- закрытое состояние — круглая кнопка с подписью «Написать
  преподавателю» и счётчиком сообщений;
- открытое состояние — панель с заголовком (аватар, имя
  преподавателя, статус), телом со списком сообщений, индикатором
  «печатает...» и полем ввода;
- авто-ответ преподавателя через 1-2 секунды; реплика подбирается
  функцией `replyFor(text)` по ключевым словам в сообщении студента.

### NewsList, TeachersList, StudentsList

Сетки карточек по соответствующим данным. Сетки адаптивные
(`grid-template-columns: repeat(auto-fill, minmax(N, 1fr))`).

## 10. Хранение данных

Используется четыре ключа в `localStorage`:

| Ключ            | Что хранит                                  |
| --------------- | ------------------------------------------- |
| `users`         | список зарегистрированных пользователей     |
| `user`          | текущий вошедший пользователь               |
| `enrollments`   | все записи на курсы всех пользователей      |
| `chat_messages` | вся история чатов всех пользователей        |

Фильтрация по `userId` происходит на уровне селекторов в Redux —
чужие записи и чужие чаты не показываются.

Сохранение работает через прямой вызов `localStorage.setItem` внутри
редьюсеров (для записей и чата) или через явное сохранение в
`authSlice`.

## 11. CRUD-функционал

Полный набор CRUD реализован для сущности «Курс»:

**Create**
- UI: кнопка «+ Добавить курс» открывает форму `<CourseForm>`.
- Action: `createCourse(courseData)` — async thunk.
- Service: `createCourseRemote` отправляет POST на JSONPlaceholder.
- Reducer: `createCourse.fulfilled` добавляет курс в state.

**Read**
- UI: список курсов на `/courses`, детальная страница `/courses/:id`.
- Action: `fetchCourses()` и `fetchCourseById(id)`.
- Service: `getAllCourses` и `getCourseById` читают локальный JSON.
- Reducer: соответствующие `.fulfilled` сохраняют данные.

**Update**
- UI: кнопка «Редактировать» открывает ту же `<CourseForm>` с
  предзаполненными данными.
- Action: `updateCourse(courseData)`.
- Service: PUT на JSONPlaceholder.
- Reducer: обновляет курс в state.

**Delete**
- UI: иконка корзины открывает модальное окно подтверждения.
- Action: `deleteCourse(id)`.
- Service: DELETE на JSONPlaceholder.
- Reducer: удаляет курс из state.

Дополнительно реализованы операции записи на курс
(`enroll` / `unenroll`) и работы с чатом (`sendUserMessage` /
`sendTeacherReply` / `clearChat`).

## 12. Поиск и фильтрация

На странице `/courses` реализованы:

**Поиск по тексту**
Поле ввода обновляет `state.ui.coursesSearch` через `setCoursesSearch`.
Селектор `selectFilteredCourses` фильтрует курсы по вхождению
поискового запроса (в нижнем регистре) в название, описание или имя
преподавателя.

**Фильтрация по уровню**
Кнопки переключают `state.ui.coursesLevel`. Возможные значения:
`all`, `Начинающий`, `Средний`, `Продвинутый`. Селектор учитывает
этот фильтр вместе с поиском.

**Empty state**
Если по комбинации фильтров не нашлось ни одного курса,
показывается сообщение «По вашему запросу курсы не найдены» с
кнопкой «Сбросить фильтры».

## 13. Обработка ошибок и состояния загрузки

Каждый async-thunk обрабатывает три фазы:

```
.addCase(fetchX.pending,   ...)  // state.loading = true
.addCase(fetchX.fulfilled, ...)  // state.loading = false, data
.addCase(fetchX.rejected,  ...)  // state.loading = false, error
```

В компонентах используется тройной паттерн:

```jsx
if (loading) return <Loader text="..." />
if (error)   return <ErrorMessage error={error} />
if (data.length === 0) return <EmptyState />
return <Content data={data} />
```

Примеры обработки в UI:
- `<CoursesList>` — `loading` → `<Loader>`, `error` → красное
  сообщение, пустой список фильтрации → empty state с кнопкой сброса.
- `<CourseDetailPage>` — loading, error (с ссылкой «Вернуться к
  курсам»), отсутствие курса → `null`.
- `<ProfilePage>` — пустой список курсов → блок с кнопкой «Смотреть
  курсы».

Все ошибки async-операций передаются через `rejectWithValue`, что
позволяет хранить понятное сообщение в `state.error`.

## 15. Проверка работоспособности

Сценарий полной проверки функционала:

1. Запустить `npm run dev`, открыть `http://localhost:5173`.
2. На главной убедиться, что подгрузились топ-3 курса, новости и
   преподаватели (видим индикатор загрузки в течение ~1.5 секунд).
3. Перейти в «Курсы», увидеть все 6 курсов и панель фильтров.
4. Ввести в поиск «React» — должен остаться один курс.
5. Очистить поиск, нажать «Продвинутый» — должен остаться один курс.
6. Нажать «Сбросить» — все 6 курсов вернутся.
7. Перейти на любой курс, нажать «Записаться на курс» —
   произойдёт редирект на /login, появится тост.
8. Зарегистрироваться. Вернуться на курс, нажать «Записаться» —
   появится тост с днём и временем занятий, кнопка станет бейджем
   «Вы записаны».
9. Открыть личный кабинет — увидеть карточку с днём, временем и
   преподавателем.
10. Открыть расписание — в «Моём расписании» появится этот курс.
11. На странице курса нажать «Написать преподавателю», отправить
    сообщение — через секунду придёт ответ.
12. На странице «Курсы» нажать «+ Добавить курс», заполнить форму,
    отправить — пойдёт POST на JSONPlaceholder, курс появится в
    списке, придёт тост «Курс добавлен».
13. Удалить курс — пойдёт DELETE на JSONPlaceholder, курс исчезнет.

Сетевые запросы можно увидеть в DevTools → Network → фильтр
`jsonplaceholder`.

## 16. Структура кода и соглашения

**Именование файлов**
- Компоненты — PascalCase: `CourseDetailPage.jsx`.
- Слайсы и сервисы — camelCase: `coursesSlice.js`.
- Утилиты — camelCase: `format.js`.

**Структура компонента/страницы**
Один каталог содержит `.jsx`, `.css` и `index.js` для реэкспорта:

```
ComponentName/
├── ComponentName.jsx
├── ComponentName.css
└── index.js
```

Это позволяет писать импорт `import X from './components/X'` без
указания файла.

**Селекторы и хуки**
Сложные селекторы вынесены из слайсов в отдельные функции
(`selectFilteredCourses`, `selectUserEnrollments` и др.). Частые
обращения к store обёрнуты в хуки: `useAuth`, `useMyEnrollments`,
`useIsEnrolled`, `useNotify`.

**Стили**
Каждый компонент имеет свой `.css`-файл, классы именуются по схеме
BEM-Lite: `block__element--modifier`. Глобальные переменные цветов
не вынесены — используются прямые градиенты `#667eea -> #764ba2`.

**ESLint**
Используется конфиг `eslint.config.js` с правилами для React Hooks
и React Refresh. Линтер запускается командой `npm run lint`.
